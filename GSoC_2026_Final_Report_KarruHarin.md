## Project Overview

The project is aimed at transforming marine biology education through immersive Augmented Reality technology! Where the application's other modes place a single creature on a tabletop, my work places an **entire seabed** on the classroom floor — and lets a teacher author a new one without writing a line of code. The same procedural ocean was built twice, once in Unity for mobile AR and once in the browser, so a lesson reaches a student on an ARCore phone or a school laptop alike.

**The Challenge**: Static textbooks fail to convey the dynamic nature of underwater ecosystems, and hand-authored 3D scenes do not fix it — a curriculum needs many environments rather than one, each costs an artist and a build, and none can be adapted by the teacher who knows the lesson.

**The Solution**: A procedural subsystem that generates an endless, streamed ocean on-device from roughly fifty numbers, anchors it to a tracked floor plane, populates it using rules taken from benthic ecology rather than art direction, and exposes all of it through an authoring layer where a teacher answers **ten questions** instead of tuning fifty parameters.

### Key Accomplishments
- Development of a two-layer authoring system: ten teacher choices expand into ~50 technical parameters, guarded by six cross-subsystem invariants re-derived on every load **and** save
- Building of an endless, thread-pooled procedural seabed that streams around a walking student in AR and regenerates bit-identically on every device
- Creation of three ocean biomes (Coral Shallows, Kelp Forest, Coral Canyons) defined as **data files rather than scenes**, generated by the same code path a teacher's environment uses
- Implementation of ecology-based coral placement — habitat patches, slope limits, surface curvature and size–frequency structure — instead of uniform scatter
- Implementation of a single shared water medium with wavelength-dependent absorption, marine snow and caustics, so every drawn surface agrees about what it is submerged in
- Establishment of a browser counterpart, **Ocean Explore**, carrying the same seabed and the same underwater shading into a URL with no install
- Implementation of a read-only World Context API so narration, quizzes and the AI tutor can ask a generated world what it contains

## Key Features

### Customizable Environments: Ten Questions, Fifty Parameters
- **A User Layer in the Teacher's Vocabulary**: Ten choices — seafloor profile, terrain complexity, seafloor surface, marine habitat, habitat density, water clarity, water colour, water movement, exploration area, visibility. A mapper expands each into the technical parameters it implies, and one choice deliberately drives several correlated systems at once, because in real water clarity, absorption, particulate and light all covary
- **Why "fewer sliders" was rejected**: "Fog density 0.055" is not a question a marine biology teacher has an opinion about, whereas whether the water is murky or clear is. And individually legal settings still combine into a broken world — terrain tall enough to erupt through the surface, visibility long enough to see the world end. Restricting ranges cannot fix that, because the problem is in the relationships between them, not in any one range
- **Six Invariants That Make Broken Worlds Unrepresentable**: fog must have a real fade band; visibility ends before the streaming reach; terrain peaks stay below the surface; one water level drives the plane, the fog and the shaders; the camera's far plane derives from visibility; a hard per-chunk scatter budget
  - **No trusted path in** — they run on *save* as well as load, so a hand-edited, older or transferred file is clamped on the way in
  - **One definition, not two** — the authoring form is generated from the same ranges the clamp enforces, so the UI cannot express an illegal value
  - **One-way flow** — the user layer is never written back from technical values, so the technical layer can change without breaking saved environments
- **Configuration Order as Code**: a chunk built one frame early keeps its defaults for its whole life, so all configuration happens in one place, in one fixed order, once, at load
- **Environments Are Data, Not Scenes**: an environment is ~50 numbers, so a new biome costs a file rather than a build — and the three shipped biomes are defined exactly as a teacher's is
- **Live Tuning vs. Rebuild**: colour, fog and lighting edits write uniforms and land on the same frame; only structural controls (terrain height and scale, snow count, life density) rebuild, and those are debounced
- **The Claim**: procedural authoring tools protect non-experts by restricting what each parameter *may be*. The failures that matter live in **relationships between parameters that span subsystems** — encoding a few as invariants makes broken worlds unrepresentable rather than unlikely, where "reachable" includes hand-edited files and not merely the UI

### Procedural Terrain Generation & AR Streaming
- **Six-Stage Pipeline, One-Way Flow**: heightfield → mesh → streaming → scatter → water medium → authoring. Stages 1 and 2 are pure functions of `(seed, coordinate, parameters)` that never touch an engine API — which is why they run on a thread pool, give identical output on every device, and let the world be thrown away and rebuilt rather than stored
- **Three Layered Noise Operators**: domain warping makes straight features meander, ridging folds a smooth contour into a sharp crest, terracing quantises heights into mesa tops with near-vertical faces. Gentle reef dunes and dramatic canyon walls therefore come from the same machinery, so streaming, meshing and collision only ever handle one thing. `Classic` is bit-identical to the original noise; `Canyons` enables all three with a taller height scale
- **Bit-Identical Seams as a Specification**: neighbouring chunks compute their shared edge twice, on different threads. Floating-point addition is not associative, so two algebraically identical computations disagree by millionths and a shimmering seam appears — **the order of operations is part of the spec** (small local terms first, large offsets last). Heights normalise against a deterministic global bound rather than per-chunk extrema for the same reason
- **Four Detail Levels, Correct Normals, Hidden Curtains**: a 33×33 chunk strides to LOD 0/1/2/4 — 3 is arithmetically impossible, not an oversight. Each chunk generates one discarded extra ring of samples so border normals agree in any order, and LOD mismatches are covered by height-scaled skirts rather than per-pair transition geometry
- **AR-Anchored Endless World**: a tap raycasts to a detected plane, creates an anchor and instantiates the ocean beneath it. Chunks keep their real-world horizontal position but take their **height from the anchor** — the one decoupling that seats a seabed on a classroom floor. Memory stays flat whether the student walks two metres or two hundred: 8 m chunks, ~64 m of live ocean, colliders only on the nearest ring
- **Caves Without Giving Up the Heightfield**: arches, overhangs, grottos, boulders and spires are seated meshes, built once at startup from a seed and shared by every instance — an infinite ocean of arches costs four arches — with colour and ambient occlusion baked into vertices and **no textures at all**
- **One Shared Water Medium**: colour, clarity and view distance are pushed out once as global shader values, so sand, rock, kelp, sky and surface can never disagree about the colour of distance. Wavelength-dependent absorption is derived from the chosen water colour (red falls off ~3× faster than blue), joined by GPU-positioned marine snow, per-pixel caustics gated to up-facing surfaces, and shader-computed encrusting life
- **Read-Only World Context API**: in a generated world nobody knows what is there — not the developers, not the teacher, not the app. `World.GetCreatures(r)`, `GetEnvironment()`, `GetPlayer()`, `Describe()` and `ToJson()` answer "what is around me?" with relative bearings, so narration, a comprehension question and an AI tutor all have something to read

### Coral & Life Placement
- **Four Rules From Ecology, Not Art Direction**: uniform scatter reads immediately as computer graphics, so placement follows rules a marine biologist would recognise — **habitat patches** (a slow noise field gates where life grows at all, so gardens alternate with open sand), **slope limits** (sessile organisms have attachment constraints), **micro-habitat by curvature** (four ground probes bias species onto exposed ridges or into sheltered hollows), and **size–frequency structure** (many small colonies, one large — coral populations are recruitment-dominated, and uniform sizes are the clearest tell of procedural placement)
- **Determinism as Pedagogical Reproducibility**: each chunk's RNG is seeded from a hash of its coordinates, so placement is a pure function of position. There is **no save file at all** — nothing to serialise, version or corrupt — and thirty students holding the same environment file see the *same* reef, which is what makes "find the sea fan on the ridge to your left" a usable instruction
- **Coherent Beds, Not Confetti**: hero corals and rocks scatter singly while bed-forming species grow as golden-angle mounds with a centre size hierarchy, and every prop leans along the terrain gradient so it seats naturally instead of standing upright on a slope
- **Scale Is Content, Not Polish**: every object is scaled to a real-world height in metres from its own bounding box, regardless of how it was exported — this is what goes silently wrong when models arrive from a dozen sources
- **Screened, Not Just Imported**: candidate coral scans were rendered from three angles before selection and grouped by growth form and depth, which is what stops a reef looking repetitive

### The Underwater World in the Browser
- **Ocean Explore**: a first-person dive into the same endless procedural seabed, built on three.js and streamed from a worker pool, reachable from a URL with no install. **No baked animation anywhere in the module** — the terrain is noise, the water and light are shaders, and the sea life is made to swim
- **The Fog Wall as a Cross-File Invariant**: the load radius sits one ring beyond the view radius, so chunks are born behind the fog and never seen appearing; late chunks fade in through a screen-door dither, and fish shoals spawn and despawn on a ring keyed to the same distance
- **Underwater Shading That Holds Together**: every flora and creature material has the terrain's fog curve injected at load — the engine's built-in fog is about half strength at distance and makes corals glow through the fog wall. Fog is evaluated on radial distance and fades toward the same direction-dependent background gradient as the seabed, without which distant corals read as floating dirt
- **Procedural Props and GPU Sway**: rocks, seagrass and kelp are built in code with no download at all (~13k triangles for the whole set), and every plant sways from a base-rooted vertex animation at zero CPU cost

## Quick Start

### Prerequisites

**Hardware Requirements:**
- AR-compatible mobile device (with ARCore/ARKit support)
- Minimum 4GB RAM
- 2GB available storage space
- *For the web build*: any WebGL2 browser — no install, no plugin

**For Development:**
- Unity 6000.3.14f1 (or newer) with URP
- AR Foundation + ARCore/ARKit XR plug-ins
- Node.js 18+ and npm (web build)
- Git

### For Educators & Students

- **Hardware Requirements:**
   - AR-compatible mobile device (with ARCore/ARKit support)
   - Minimum 4GB RAM
   - 2GB available storage space

1. **Pick a Surface**
   - [MarineBiology_AR](https://github.com/Catrobat/mARine) for Android — the full AR app
   - Or open the web build in a browser and sign in — nothing to install

2. **Get Started**
   - Launch the app and scan a flat floor, then tap to place the ocean
   - Or open `/ocean-explore` in the browser and dive straight in
   - Use **Create Environment** to build a new ocean by answering ten questions
   - Share the environment file (or the class code) with your students

### For Developers

- **Hardware Requirements:**
   - Discrete GPU (RTX 2050 or higher recommended)
   - Minimum 8GB RAM
   - 25GB available storage space

1. **Clone the Repositories**
   ```bash
   # The Unity AR application
   git clone https://github.com/Catrobat/mARine.git


   # The Marine Web AR platform
   git clone https://github.com/KarruHarin/marine_book_web_ar.git
   ```

2. **Open in Unity**
   ```bash
   # Editor version
   Install Unity 6000.3.14f1 (or newer) with Android/iOS build support.

   # Open the project from Unity Hub
   From Unity Hub, click Add Project and select the cloned folder.

   # Unity will resolve packages and dependencies on first import
   ```

3. **Build Settings**
   - Go to File → Build Settings.
   - Choose Android or iOS as target platform, then Switch Platform.
   - Enable ARCore/ARKit in XR Plug-in Management.
   - Confirm the Universal Render Pipeline asset is assigned in Graphics settings.

4. **Run the Web Build**
   ```bash
   cd marine_book_web_ar
   npm install
   npm run dev        # local dev server
   npm run build      # production bundle in dist/
   ```

5. **Run the Tests**
   ```bash
   /Applications/Unity/Hub/Editor/6000.3.14f1/Unity.app/Contents/MacOS/Unity \
     -batchmode -nographics -projectPath . \
     -runTests -testPlatform EditMode -testResults results.xml
   ```

## Project Structure

```
Marine AR (Unity)
└── Assets/ProceduralTerrain/
    ├── CreateEnv/                 # The authoring layer
    │   ├── SimpleEnvironmentSettings.cs   # the ten teacher-facing choices
    │   ├── SimpleEnvironmentMapper.cs     # ten -> ~fifty, plus the clamp
    │   ├── EnvironmentProfile.cs          # the technical parameter set
    │   ├── EnvironmentRepository.cs       # load/save, invariants on both
    │   ├── EnvironmentLoader.cs           # one place, one fixed order, once
    │   ├── BuiltInProfiles.cs             # the three shipped biomes, as data
    │   └── UI/                            # form generated from the ranges
    ├── Scripts/                   # The generation pipeline
    │   ├── Noise.cs                       # fractal sum, warp, ridge, terrace
    │   ├── TerrainShaper.cs               # Classic / Canyons styles
    │   ├── MeshGenerator.cs               # heightfield -> mesh, 4 LODs
    │   ├── EndlessTerrain.cs              # chunk streaming + colliders
    │   ├── EndlessTerrainPlacer.cs        # AR anchor coupling
    │   ├── TerrainDetailScatter.cs        # ecology-based coral/flora placement
    │   ├── ProceduralFeatureScatter.cs    # arches, grottos, overhangs
    │   ├── ProceduralMeshLibrary.cs       # shared seated feature meshes
    │   ├── UnderwaterEnvironment.cs       # the shared water medium
    │   ├── Minimap/                       # radar, markers, registry
    │   └── WorldContext/World.cs          # read-only scene description API
    ├── Shaders/                   # UnderwaterRock / Kelp / Glow (URP, no textures)
    └── Materials/, Prefabs/, coral_prefabs/

Marine Web AR (React + three.js)
└── src/components/OceanExplore/
    ├── OceanExplore.jsx           # React shell: canvas, HUD, environment switching
    ├── EnvControls.jsx            # the live "Custom" tuning panel
    ├── engine/                    # OceanWorld, swimmer, vision, hearing, senses
    ├── game/                      # species catalogue, creatures, survey, dive log
    └── terrain/                   # noise, worker pool, shaders, props, fauna

Procedural-Terrain-Generation (standalone engine + demo)
└── Assets/Scenes/                # SampleScene, KelpForest, CoralCanyons, CreateEnv flow
```

## Usage Guide

### For Educators

1. **Build an Ocean**
   - Open **Create Environment** and answer ten questions — seafloor profile, terrain complexity, surface, habitat, habitat density, water clarity, colour, movement, area and visibility
   - Preview it immediately; every answer is legal by construction, so there is no way to produce a broken world
   - Save it as a file — an environment is about fifty numbers, not a scene

2. **Classroom Implementation**
   - Share the environment file (or class code) with students
   - Because generation is deterministic, every student sees the *same* reef
   - Set the same lesson on phones and on laptops; the browser build carries the same seabed and the same water
   - Facilitate discussion from what students actually found, not from what was scripted

### For Students

1. **Access the Ocean**
   - Scan a flat floor and tap to place the ocean, or open the web build and dive
   - Follow the guided onboarding, then swim freely — the world streams around you as you walk

2. **Explore & Learn**
   - Swim the reef, the kelp forest and the canyons, and see how habitat, slope and shelter decide what grows where
   - Log species by observing them; the Dive Log fills as you go
   - Unlock and **become** a turtle, octopus, dolphin or great white, and experience the same water through that animal's senses
   - Walk back the way you came — the reef regenerates exactly as you left it

## Contributing

We welcome contributions from educators, developers, marine biologists, and educational technology specialists!

### Ways to Contribute
- **Environments**: Author and contribute new biomes — they are files, not builds
- **Technical Development**: Implement features, optimise performance, fix bugs
- **Scientific Accuracy**: Validate the placement rules and species data
- **Accessibility**: Extend the World Context API into richer narration for visually impaired students
- **Documentation**: Enhance guides, architecture docs and educational resources

### Contribution Process

1. **Fork & Clone**
   ```bash
   git clone https://github.com/Catrobat/mARine.git
   ```

2. **Create Feature Branch**
   ```bash
   git checkout -b feature/your-enhancement
   ```

3. **Develop & Test**
   - Run the EditMode tests, and re-check the six invariants if you touched the authoring layer
   - If you change fog values or streaming radii, re-check that the spawn frontier still sits beyond visibility

4. **Submit Pull Request**
   - Include detailed description
   - Add educational rationale and technical notes

## Future Goals

### Short-term (3-6 months)
- **Open Environment Format**: Biomes contributed as files rather than builds, so ecosystems we have never modelled can be authored by the people who know them best
- **Invariant Coverage Harness**: Enumerate the authoring space and assert all six invariants at every point, plus a fuzz pass over hand-edited files
- **Placement Ablation & Boundary Tests**: One species scattered with the curvature parameter negative, zero and positive; visibility and area at their extremes to show the world's edge never appears

### Long-term (6-12 months)
- **Collaborative Sessions**: Determinism means two students in different rooms can occupy the same reef with almost nothing synchronised
- **Generated Narration & Assessment**: Produced from the World Context API rather than hand-authored per scene
- **Richer Substrate**: More rules from benthic ecology — current exposure, sediment type, depth-banded species pools — driven by the same ten choices
